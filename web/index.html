Errors above 1 (the method has blown up) and below 10⁻¹² (round-off) are left out of the fit. RK45 is adaptive: its error is set by its tolerance, so it does not change with h. With a pulse force, fixed-step methods use the force averaged over each step, so each step gets the right impulse. Step sizes are adjusted slightly so the pulse start and end fall on grid points; if a jump fell between grid points, RK4 would drop to second order.

Resonance curves

Steady-state amplitude of the response to F₀ cos(ωt) for several damping coefficients, using m and k from the sidebar. The exact amplitude is A(ω) = F₀ / √((k − mω²)² + (bω)²).

RK4 runs start from x₀, v₀ in the sidebar; the amplitude is the largest |x| over the last quarter of the run. It only matches the steady state if transients have decayed, i.e. if the run is several decay times 2m/b long.

Equation of motion

m ẍ + b ẋ + k x = F(t), written as the first-order system ẋ = v, v̇ = a(x, v, t) = (F(t) − b v − k x)/m. Natural frequency ω₀ = √(k/m), decay rate γ = b/2m, critical damping bcr = 2√(km), damping ratio ζ = b/bcr, quality factor Q = mω₀/b = 1/(2ζ).

Exact solution

The free response is written in one form for every regime:

x(t) = e−γt [x₀ C(t) + (v₀ + γx₀) S(t)]

  • underdamped (ζ < 1): C = cos ωdt, S = sin(ωdt)/ωd, with ωd = √(ω₀² − γ²)
  • critically damped (ζ = 1): C = 1, S = t
  • overdamped (ζ > 1): C = cosh rt, S = sinh(rt)/r, with r = √(γ² − ω₀²)

For a rectangular pulse of force F, x − F/k obeys the free equation while the force acts, so the solution is joined from three free solutions. For a sinusoidal force the solution is the steady state A cos(ωt + φ − δ), with tan δ = bω/(k − mω²), plus the free response that matches the initial conditions. Because the exact solution is available in all these cases, every error shown in this app is a true error.

Integration methods

MethodGlobal orderDescription

Global order p means the error at a fixed time falls as hp. A method that is 2nd order locally (one step) is 1st order globally, which is why the notebook's “O(h³)” for Improved Euler is not what you observe.

Energy

The mechanical energy E = ½mv² + ½kx² decays because of damping (and changes when a force acts). The energy plot compares each method's energy with the exact energy. Explicit Euler always gains energy for an undamped system; Euler-Cromer and Verlet are symplectic, so for b = 0 their energy oscillates around the true value without drifting.

Review of the original notebook

The original version of Numerical_integration.ipynb had a sound overall approach (compare several integrators against an analytic solution, then study driven motion and resonance), but a few problems affected its conclusions. They are listed below. Both this app and the current notebook fix them; the notebook starts with a revision note and its observations and conclusion were rewritten for the corrected results. One more bug was found while correcting it: the analytic energy formula had the wrong sign on one velocity term.

Problems that change the results

  1. The Runge-Kutta results are compared at the wrong times. RungeKutta integrates to nsteps·h and reports nsteps points with linspace, so its spacing is nsteps·h/(nsteps−1), not h. The analytic solution is evaluated on arange(0, T, h). At h = 0.1 s, T = 300 s the times drift apart by up to 0.1 s, which doubles the reported RK error (MAE 0.0124 m instead of 0.0058 m for b = 0.1). With aligned times RK beats Euler-Cromer there too, so “Euler-Cromer is best for b = 0.1” is an artefact.
  2. “Runge-Kutta” is SciPy's adaptive RK45 with default tolerances (rtol = 10⁻³), not the fixed-step RK4 described in the text. Its step size does not depend on h, so its error is the same for every h (about 1.06 × 10⁻³ m MAE for b = 0.5 kg/s, T = 50 s at h = 0.1, 0.05 and 0.01 s). The step-size study therefore says nothing about RK accuracy. This app has a true RK4 and keeps RK45 separately with a tolerance setting.
  3. The Verlet method is only first order. It uses v[i], computed as (x[i] − x[i−2])/2h, which is the velocity one step back, in the damping force. Its error halves (rather than quarters) when h halves, which is why it “gets worse as damping increases”. Velocity Verlet with the damping force treated implicitly is second order.
  4. Analytic curves on the wrong grid in the critical-damping comparisons. In plot_simulation_results_with_analytical and calculate_mae_for_damping_types the analytic solution uses linspace(0, T, nsteps) (spacing T/(nsteps−1)), while the numerical methods use spacing h.
  5. Critical damping is detected with b == b_cr on floating-point numbers, which only works because the same expression is used twice. A tolerance (or one formula valid for all regimes, as here) is more robust.
  6. The driven-motion plots compare with the unforced solution, labelled “Analytical Solution”. The forced problem has an exact solution, so the numerical error of the driven runs can be measured directly.
  7. The resonance curve uses the maximum |x| over the whole run, including the start-up transient and the initial velocity. For b = 0.1 kg/s the 150 s run lasts only 1.3 decay times (2m/b = 112 s), so the transient has not died out. The steady-state amplitude should be taken after the transient has decayed (or computed exactly).

Errors in the text

  • Improved Euler is said to have error O(h³). Only the position update gets the extra term, so the method is first order overall.
  • The Verlet formula reads xi+1 = 2xi + xi−1 + h²ai; it should be − xi−1.
  • The Euler-Cromer formula is written vi+1 = vi + (hk/m)xi: the sign is wrong and the damping term is missing (the code is correct).
  • The section heading says “Runge-Kutta 45” but describes RK4; the code uses RK45.
  • MSE is quoted in m; its unit is m².
  • The sinusoidal force is written F₀ sin(ωt + φ) in the introduction and F₀ cos(ωt + φ) later (the code uses cos). The sudden force is introduced as a Dirac delta but simulated as a 3 s rectangular pulse.

Code quality

  • The integrators read m and k from global variables; the force phase φ is also a global inside sinusoidal_force.
  • Number of steps is computed in three different ways (ceil(T/h), int(T/h) and arange), which can disagree by one point for some T and h.
  • The same plotting and error code is repeated in several cells, and run_simulation_best is called three times per step size where once would do.
  • No tests. This package has tests that check the exact solutions and the order of every method.
